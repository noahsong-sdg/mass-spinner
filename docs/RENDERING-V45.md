## Execution path and causes

Accepted centrifuge results enter `setupFuelCentrifuge.showGeometry`, which supplies a parametric Three.js assembly and camera to `createApparatusViewer`. Other numerical playgrounds use the same viewer and engineering-geometry builder through their surface layer. The actual deployed starting image was checked before editing.

| Problem | Technical cause / simple explanation | Fix and reason for this choice |
|---|---|---|
| Flattened metallic appearance | High hemisphere/fill lighting plus exposure reduced local contrast. Nearly every surface received strong light, hiding depth. | Reduced ambient illumination and exposure; retained environment reflections and introduced directional key/fill/rim separation. This fixes illumination rather than changing scientific geometry or adding decorative glow. |
| Soft, implausible ring edges | Shared indexed vertices averaged axial, cylindrical and cut-face normals. Flat faces shaded as though rounded. | Separate face vertices and analytical outward normals, with small construction chamfers and UVs. Chamfers stay inside original radial/axial extrema. Unlike flat shading, this preserves smooth cylinders and gives real edge highlights. No chamfer is added to the physical target film. |
| Indistinct metal/ceramic finishes | Uniform roughness made the materials read like similar plastic surfaces. | Physical metal materials with directional highlights and deterministic non-color roughness textures; distinct copper, steel, refractory, ceramic and matte support finishes. Optical parameters are illustrative, not measured alloys or thermal fields. No remote texture dependency or image overlay. |
| Amber/brown shell at startup | Initializing the inspector called the same highlighting path as an explicit user selection. Merely filling the component menu recolored the vessel and base. | Track whether a user has selected anything; populate the default description without highlighting. Explicit selections still survive accepted updates and existing removed-component behavior is retained. Reducing highlight brightness would only conceal the incorrect initial state. |
| Support looked like a backdrop | The centrifuge camera used a transverse up vector and nearly overhead inspection angle. The base occupied the plane behind the assembly. | Upright three-quarter reference camera, still viewing the cutaway. Existing orbit, zoom, focus and reset remain available. Other playgrounds retain their camera frames. |
| Weak contact depth | No hardware shadow map. Parts lacked mutual occlusion from the key light. | SI-bounds-framed hardware shadows, cached until geometry/framing changes and explicitly disposed with the viewer. Numerical overlays do not cast shadows. This adds physical depth without an animation loop or expensive postprocessing chain. |
| Schematic stages resembled physical barriers | Ideal routing partitions used opaque metal disks within one reference vessel. The illustration implied bulkheads the reduced model does not solve. | Thin translucent routing outlines with existing explicit schematic metadata. Accepted stage count and return routing remain inspectable, without inventing as-built partitions. |
| Lighting changed quantitative color appearance | Composition rings used lit metal-like shading. Their color could darken or brighten with the camera/light relationship. | Unlit composition colors and disabled depth writes preserve their numerical meaning while physical hardware retains realistic lighting. Null composition remains neutral rather than fabricated. |

Implementation follows Three.js [physical material](https://threejs.org/docs/pages/MeshPhysicalMaterial.html) and [prefiltered environment lighting](https://threejs.org/docs/pages/PMREMGenerator.html) documentation. This is interactive GPU geometry, not a static render or a new Blender asset. New finish textures are released with the owning scene; selection material clones share, rather than dispose, those textures.
