## Paths examined and source conclusions

- **Displayed representation:** `apparatus-ui.js` receives representation events from `apparatus-viewer.js`, which derives accepted/reference/none state from the actual displayed root. The existing Concept model disclosure now follows accepted fields, trajectories, impacts, hardware-only, pending/reference, loading and error states. A ready input alone does not update the disclosure before the viewer displays it. Construction and material caveats remain separate from true SI numerical geometry. `surface-layer.js` reports whether the selected overlay actually has numerical children, including empty-track/impact cases. Source design is coherent; the v43 apparatus-representation regression covers the intended messages but its execution result is pending here.
- **Camera frame:** `apparatus-viewer.js:88–105` disposes the old OrbitControls, removes its render listener and constructs fresh controls when up changes. This addresses OrbitControls' cached up transform rather than merely copying camera.up. Accepted geometry uses transformed local +x as up and local +y as the open-cutaway sightline; transformed axial +z remains screen-right. Keyboard orbit applies the same up frame. The replacement controls receive the target and the reset path restores limits. Final disposal targets the current controls. `viewer-frame-v43.test.ts` uses real OrbitControls with a stub renderer, a meaningful distinction from a no-op controls mock; execution and GPU/mobile observation remain pending.
- **Resize and deliberate zoom:** resize scales the camera-to-target offset by new-fit/old-fit distance and retains the target and orbit direction. This preserves the user's relative zoom while adapting to horizontal field of view. Ordinary accepted field/time refresh with the same geometry does not reset the camera. This is preferable to resetting every resize or silently clipping a formerly fitted model. The added test checks both representations, narrow fitting, focused target and intentional zoom; browser framing remains a gate.
- **Impact picking:** rendered impacts disable depth testing and use a single ordered Points batch. The pointer path filters by the screen-space footprint, then prioritizes those visible impact points over foreground hardware, using later vertex order for overlapping dots. Noninspectable lines are excluded and ordinary hardware remains the fallback away from dots. This now matches the drawing policy. The actual ray/point path is covered in `viewer-frame-v43.test.ts`; no GPU rasterization or touch result is claimed from source.
- **Mobile data/overlays:** `style.css:72–73` uses zero-minimum tensor tracks/children and stacks tensors at <=740px, with local preformatted/table scrolling. `workspace-ui.js:23–25` reserves the measured dock height plus bottom offset and gap, then updates via window resize and dock ResizeObserver. The apparatus disclosure uses that reserve and bounds its own scroll height. These address the original ownership conflicts instead of exchanging z-index priority. Reachability at 320/390px, short height and 200% zoom remains a browser gate.
- **Landmark/model chooser:** workspace is now a named main and owns the existing h1; the old main is hidden after the live nodes move. The original mechanism select and its listeners move into a persistent Models context with an explicit name and visually hidden native label. This avoids duplicate state. Current h1 text still comes from experience refresh. Browser AX naming, focus continuity and one-change/one-simulation behavior remain to be observed.
- **Exposure units, adjacent correctness:** the explicit Celsius domain is now only coolantK/initialK. Both capacity and cooling conductance end in K but are coefficients, so they must not acquire a +273.15 offset or lose 273.15 in display. Current read/readout code converts actual temperatures exactly once; logarithmic capacity metadata gives precise controls physical J m^-2 K^-1 bounds and values, while the linear cooling editor remains in W m^-2 K^-1. The independent source trace agrees with the new expected defaults C=10000, h=5000 and tau=2 s. The nested real-UI regression also checks non-grid capacity/cooling/Celsius entry, exports, invalid bounds and Reset. Its execution is pending here.
